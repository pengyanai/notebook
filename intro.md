# Introduction

A minimal, fast blog built on Jekyll and GitHub Pages. Content is driven by **GitHub Issues**—write in Issues, publish on the web.

---
## Minimal Design

- **Clean layout** — No top bar, no footer, no clutter. A single-line header with the site title and search. Content first.
- **shadcn/ui–inspired styling** — Neutral palette, subtle borders, muted backgrounds. Looks good in light and dark mode.
- **Responsive** — Works well on phones, tablets, and desktops. Wide reading area (up to 1400px) for comfortable reading.
- **System fonts** — Uses `ui-sans-serif`, `system-ui`, and system fonts for fast loading and native look.
- **CJK typography** — Optimized font stack (PingFang SC, Hiragino Sans GB, Microsoft YaHei, etc.), antialiasing, `font-synthesis: none` to prevent blurry synthetic italic for Chinese/Japanese/Korean characters.

---
## Main Features

| Feature | Description |
|--------|-------------|
| **Issue-driven content** | Create and edit posts via GitHub Issues. Add label `blog` to publish. A single `run.py generate` syncs issues to local posts. |
| **Full-text search** | Client-side search over titles, content, metadata. Press `⌘ + K` or `/` to open. Fuzzy matching via Fuse.js. |
| **Math formulas** | LaTeX math with MathJax. Supports inline `$...$` and display `$$...$$`. |
| **Mermaid diagrams** | Flowcharts, sequence diagrams, and more via ` ```mermaid ` code blocks. |
| **Code highlighting** | Syntax highlighting with Rouge. |
| **RSS feed** | Built-in feed for subscriptions. |
| **SEO** | Auto-generated meta tags via jekyll-seo-tag. |
| **CJK rendering** | Sharp, clear CJK text via font stack, `-webkit-font-smoothing`, `font-synthesis: none`, and `font-feature-settings`. |

---
## Performance

- **Static site** — Plain HTML/CSS/JS. No server-side rendering or database.
- **Small asset footprint** — One main stylesheet, compressed with SASS. Minimal third-party scripts.
- **Lazy loading** — Images use `loading="lazy"` and `decoding="async"` to keep initial load fast.
- **Content visibility** — `content-visibility: auto` defers rendering of off-screen post content until near the viewport.
- **Search without extra latency** — Search index is a single JSON file. Matching runs in the browser; no backend call.
- **Preconnect** — Early connection to GitHub and CDNs used by posts.
- **Hosted on GitHub Pages** — Served via CDN for quick delivery worldwide.

## Project Structure

```
├── _config.yml          # Site config: title, baseurl, kramdown, plugins, exclude
├── _includes/           # Reusable HTML partials
│   ├── head.html        # <head> content (meta, CSS, MathJax)
│   ├── header.html      # Site header (title + search bar)
│   └── search-modal.html # Search modal UI + Fuse.js logic
├── _layouts/
│   └── default.html     # Base layout: header, main content, Mermaid init
├── assets/css/
│   └── style.scss       # Custom styles (shadcn-inspired, overrides minima)
├── posts/               # Markdown posts (one .md per post)
├── index.html           # Home page (renders README.md)
├── search.json          # Search index (generated by Jekyll)
├── run.py               # Single entry for all tooling
├── scripts/             # Python helpers
│   ├── generate.py      # Issues → posts + README
│   ├── add_image_attrs.py
│   └── migrate_front_matter.py
└── .github/workflows/   # CI: generate on issue events, deploy on push
```

**Flow:** GitHub Issues (label `blog`) → `run.py generate` → `posts/*.md` + `README.md` → Jekyll build → `_site/` → deploy.

## Extending & Customizing

### Layouts

The default layout (`_layouts/default.html`) wraps all pages with header, search modal, and main content. To add a new layout:

1. Create `_layouts/your_layout.html` that extends or parallels `default.html`:
   ```liquid
   ---
   layout: default
   ---
   <div class="your-wrapper">
     {{ content }}
   </div>
   ```
2. Or build a standalone layout by copying `default.html` and changing the structure.
3. Use it in front matter: `layout: your_layout` in any page or post.

Pages without `page.title` or with `layout: home` render raw `{{ content }}` (no article wrapper). The home page uses this for the README list.

### Includes

- **`_includes/head.html`** — Add meta tags, analytics, or extra CSS/JS here.
- **`_includes/header.html`** — Change the header structure, logo, or navigation.
- **`_includes/search-modal.html`** — Customize search UI, keyboard shortcuts, or swap Fuse.js for another engine.

Include a partial in any layout or page: `{% include head.html %}`.

### Styles

All custom CSS lives in `assets/css/style.scss`. It imports the minima theme and overrides it. Change:

- **Colors / tokens** — Edit the `:root` CSS variables (light/dark).
- **Layout** — `.wrapper` max-width, `.post` structure, `.site-header`.
- **Components** — `.post-meta`, `.search-modal-box`, blockquotes, code blocks.
- **CJK typography** — `body` uses a CJK font stack and `font-synthesis: none`; `article` has `font-feature-settings: "kern" 1, "liga" 1` and antialiasing for sharp Chinese/Japanese/Korean rendering.

Run `bundle exec jekyll build` to recompile SASS.

### Config

In `_config.yml` you can adjust:

- `title`, `description`, `url`, `baseurl`
- `kramdown` for math/markdown
- `plugins` (e.g. add jekyll-sitemap)
- `exclude` to skip files from the build

### Custom Pages

Create a new page, e.g. `about.md`:

```yaml
---
layout: default
title: About
---
Your content here.
```

It will use the default layout and show the article wrapper (title + meta + content).

### Content & Tooling

- **New post source** — Extend `scripts/generate.py` to pull from another source (e.g. Notion API) and write into `posts/`.
- **Search index** — Jekyll generates `search.json` from a custom collection or data file. Adjust the structure if you change how posts are stored.
